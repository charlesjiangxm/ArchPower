# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

ArchPower is an open-source dataset and benchmark suite for **architecture-level CPU power modeling** using machine learning. It contains 200 data samples from two RISC-V CPU architectures (BOOM: 15 configs x 8 workloads = 120 samples; XiangShan/XS: 10 configs x 8 workloads = 80 samples). Features are 101-dimensional vectors mixing hardware parameters (indices 0-13, constant per config) and event parameters (81 dimensions, vary across workloads). Labels provide fine-grained power decomposed into 12 components x 5 power groups.

## Running the Benchmark Models

All scripts must be run from the `src/` directory (they use relative paths like `../dataset/`):

```bash
cd src
python McPAT-Calib.py              # Total-power-only XGBoost calibration
python McPAT-Calib-Component.py    # Per-component XGBoost (11 independent models)
python McPAT-Calib-CompGroup.py    # Per-component + per-power-group (4 groups x 11 components)
python PANDA.py                    # Physics-aware model with encode/decode resource functions
python build_event_dataset.py      # Generate event-only dataset (removes HW dependence from labels)
python event_attention.py          # FT-Transformer attention discovery (requires PyTorch)
```

Figures are saved to `../figure/<model_name>/` and attention outputs to `../output/attention_<arch>/`.

## Architecture

### Dataset Layout

- `dataset/feature.npy` — (200, 101) global feature matrix
- `dataset/label.npy` — reshapes to (200, 12, 5): 12 components x 5 power groups
- `dataset/label_28.npy` — 28nm technology node labels (same shape)
- `dataset/component_feature/*.npy` — per-component feature subsets (extracted via `component_mask.npy`)
- `dataset/event_dataset/` — hardware-normalized event-only dataset (generated by `build_event_dataset.py`)

### Label Structure

- Dimension 1 (12): `[Total, BP, ICache, IFU, RNU, LSU, DCache, Regfile, ISU, ROB, FU-Pool, Others]`
- Dimension 2 (5): `[total_power, combinational_logic, sequential_logic, memory, clock]`

### Data Splits by Architecture

Samples 0-119 = BOOM, samples 120-199 = XS. Within each architecture, samples are grouped in blocks of 8 (one config x 8 workloads). Training/testing splits are done at the **config level** (indices into config groups, not individual samples), then expanded to sample indices by multiplying by 8.

### Model Hierarchy (increasing complexity)

1. **McPAT-Calib** (`McPAT-Calib.py`): Single XGBoost model predicting total power from the "Others" component features.
2. **McPAT-Calib-Component** (`McPAT-Calib-Component.py`): 11 independent XGBoost models, one per component, using component-specific features. Total = sum of component predictions.
3. **McPAT-Calib-CompGroup** (`McPAT-Calib-CompGroup.py`): Same as above but trains separate models for each of 4 power groups (combinational, sequential, memory, clock), then sums across groups.
4. **PANDA** (`PANDA.py`): Adds physics-aware encode/decode via resource functions (`encode_arch_knowledge`/`decode_arch_knowledge`). Labels are divided by hardware-dependent scale factors before training, then predictions are multiplied back. See `doc/event_dataset_generation.md` for resource function details.
5. **Event Attention** (`event_attention.py`): FT-Transformer on the event-only dataset. Includes optional self-supervised pre-training (masked feature modeling), supervised multi-target regression, and attention map extraction/visualization.

### Shared Code Pattern

`DataLoader.py` is imported via `from DataLoader import *` by all XGBoost-based models. It defines the component list (`comp`), feature index ranges (`feature_of_components`), and the `encode_table` used by PANDA's resource functions. It loads data eagerly at import time.

### Key Domain Concepts

- **Resource functions** (PANDA): hardware-dependent scale factors per component. Multiplicative for most components, additive for Regfile, lookup-table for ISU, identity for FU-Pool. The `logic_bias` in PANDA is effectively 0 due to a Python scoping issue (intentionally preserved).
- **Event-only dataset**: created by `build_event_dataset.py`, strips hardware parameters from features (101d → 81d) and divides labels by resource functions to remove hardware dependence.
- Metrics: Pearson correlation coefficient (R) and MAPE, displayed on scatter plots.
