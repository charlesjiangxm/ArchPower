# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

ArchPower is an open-source dataset and benchmark suite for **architecture-level CPU power modeling** using machine learning. It contains 200 data samples from two RISC-V CPU architectures (BOOM: 15 configs x 8 workloads = 120 samples; XiangShan/XS: 10 configs x 8 workloads = 80 samples). Features are 101-dimensional vectors mixing hardware parameters (indices 0-13, constant per config) and event parameters (81 dimensions, vary across workloads). Labels provide fine-grained power decomposed into 12 components x 5 power groups.

## Running the Benchmark Models

All scripts use relative paths (e.g. `../dataset/`) and **must be run from the `src/` directory**:

```bash
cd src

# XGBoost benchmarks — no CLI args; loop over hardcoded train/test splits for both archs
python McPAT-Calib.py              # Total-power-only XGBoost calibration
python McPAT-Calib-Component.py    # Per-component XGBoost (11 independent models)
python McPAT-Calib-CompGroup.py    # Per-component + per-power-group (4 groups x 11 components)
python PANDA.py                    # Physics-aware model with encode/decode resource functions

# Event-dataset generation — regenerate after any change to feature.npy / label.npy
python build_event_dataset.py      # Writes dataset/event_dataset/{BOOM,XS}_event_{feature,label}.npy

# Event-dataset models — accept CLI args; run per-architecture
python event_linear.py  --arch XS                          # Ridge baseline
python event_gbdt.py    --arch XS --n_estimators 200       # XGBoost on event features
python event_mlp.py     --arch XS --hidden_layers 256,128  # 3-layer MLP baseline
python event_attention.py --arch XS                        # FT-Transformer (requires PyTorch)
```

For interactive analysis (feature importance, tree viz, SHAP), use the notebooks in `script/`, e.g. `script/event_gbdt.ipynb`. They import from `src/` and are intended as the user-facing interface.

XGBoost-benchmark figures save to `../figure/<model_name>/`. Event-dataset model outputs (reports, plots, attention maps) save to `../output/<model>_<arch>/`.

## Architecture

### Two Script Families

1. **XGBoost benchmarks** (`McPAT-Calib*.py`, `PANDA.py`): import `from DataLoader import *`, which eagerly loads `dataset/feature.npy` and all per-component feature files at import time and exposes `comp`, `feature_of_components`, and `encode_table`. No CLI — scripts loop over hardcoded split configurations (evenly / small / large) for both architectures.
2. **Event-dataset models** (`event_*.py`): use `event_utils.py` for shared loading, normalization, config-level train/val splitting, metrics, and markdown report generation. Use `argparse`. All share `prepare_data_numpy(arch, val_ratio, seed)` so they're evaluated on the same validation set.

### `src/` vs `script/`

- `src/` holds reusable modules. `event_gbdt.py` is both importable (functions like `train_models`, `predict_both`, `plot_*`, `compute_shap_values`, `write_report`) and runnable as a CLI for the quick train+report flow.
- `script/` holds user-facing Jupyter notebooks that import from `src/`. Notebooks prepend `../src` to `sys.path` and write outputs to `../output/<model>_<arch>/` (same location as the CLI, since `script/` is a sibling of `src/`).

### Dataset Layout

- `dataset/feature.npy` — (200, 101) global feature matrix
- `dataset/label.npy` — flat array; must be reshaped to (200, 12, 5) via `label.reshape((200, 12, 5))`
- `dataset/label_28.npy` — 28nm technology node labels (same shape)
- `dataset/component_feature/*.npy` — per-component feature subsets extracted via `component_mask.npy`. Note: `Others.npy` is the full 101-d feature vector (identical to `feature.npy`).
- `dataset/event_dataset/` — hardware-normalized event-only dataset (generated by `build_event_dataset.py`)
- `dataset/statistics/<config>_<workload>/` — raw gem5 statistics per (config, workload) pair

### Label Structure

- Axis 0 (12 components): `[Total, BP, ICache, IFU, RNU, LSU, DCache, Regfile, ISU, ROB, FU-Pool, Others]`
- Axis 1 (5 power groups): `[total_power, combinational_logic, sequential_logic, memory, clock]`

### Data Splits by Architecture

Samples 0-119 = BOOM, samples 120-199 = XS. Within each architecture, samples are grouped in blocks of 8 (one config x 8 workloads). Training/testing splits are done at the **config level** (indices into config groups, not individual samples), then expanded to sample indices by multiplying by 8. This prevents leakage between configs.

### Model Hierarchy (increasing complexity)

1. **McPAT-Calib** (`McPAT-Calib.py`): Single XGBoost model predicting total power from the "Others" component features.
2. **McPAT-Calib-Component** (`McPAT-Calib-Component.py`): 11 independent XGBoost models, one per component, using component-specific features. Total = sum of component predictions.
3. **McPAT-Calib-CompGroup** (`McPAT-Calib-CompGroup.py`): Same as above but trains separate models for each of 4 power groups (combinational, sequential, memory, clock), then sums across groups.
4. **PANDA** (`PANDA.py`): Adds physics-aware encode/decode via resource functions (`encode_arch_knowledge`/`decode_arch_knowledge`). Labels are divided by hardware-dependent scale factors before training, then predictions are multiplied back. See `doc/event_dataset_generation.md` for resource function details.
5. **Event-dataset baselines** (`event_linear.py`, `event_gbdt.py`, `event_mlp.py`): Ridge / XGBoost / MLP regressors mapping 81 event features → 12 power components. Share `event_utils` so metrics and splits are comparable.
6. **Event Attention** (`event_attention.py`): FT-Transformer on the event-only dataset. Optional self-supervised pre-training (masked feature modeling), supervised multi-target regression, and attention map extraction/visualization.

### Key Domain Concepts

- **Resource functions** (PANDA): hardware-dependent scale factors per component. Multiplicative for most components, additive for Regfile, lookup-table for ISU, identity for FU-Pool (no `encode_table` entry). In `PANDA.py`, `logic_bias` and `dtlb_bias` are effectively 0 because `estimate_bias_logic` / `estimate_bias_dtlb` assign to local variables rather than the module-level ones — this is intentionally preserved.
- **Event-only dataset**: created by `build_event_dataset.py`. Strips the 20 hardware-parameter columns (constant within a config) from features (101d → 81d) and divides labels by resource functions to remove hardware dependence. Must be regenerated if the raw dataset changes.
- **Metrics**: XGBoost benchmarks use Pearson correlation (R) and MAPE on scatter plots. `event_utils.compute_metrics` returns MAPE, RMSE, and R² (scikit-learn `r2_score`) — not R.

### Shared-Module Conventions

- `DataLoader.py` is a shared import module (not a standalone script). Editing it affects every XGBoost-based model.
- `event_utils.py` is the equivalent shared module for the event-dataset models; `prepare_data_numpy` is the single source of truth for the normalization and config-level train/val split.
